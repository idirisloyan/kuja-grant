## Observations (not filed as defects — automation/robustness notes)
- **Stale-persona on in-tab re-login — FIXED `e6e4421d9`.** Root cause was the **service worker** (`public/sw.js`), which stale-while-revalidate-cached `/api/auth/me` keyed by URL (not by session cookie) — so after a session change it served the PREVIOUS user's identity+role synchronously, and every role-gated control rendered for the wrong user until the browser cache was cleared. Removed `/auth/me` from the SW allow-list, bumped `CACHE_VERSION` (v15→v16, purges the poisoned bucket), and purge the `*-api` cache on login/logout. (This same SW cache also explains much of the "stale read" friction seen throughout testing.)
- **Report submit lives on the `/reports` LIST view, not the report detail page**: the detail page (`/reports/[id]`) is a view/evidence surface with no submit control; submission is the `PreSubmitReviewPanel` (precheck → Submit → `POST /reports/{id}/submit`) on the list cards. Endpoint verified live (draft→submitted→reverted); button correctly wired (unlike SMK-016). UX note: an NGO opening the report detail to submit won't find a control there.
- **Stale-SWR after a mid-session grant edit**: editing grant criteria while a review page was open served the pre-edit (keyless) grant from SWR cache, briefly coupling the two criterion score inputs into one. A hard reload fixed it. Not reproducible on a normally-created grant (wizard assigns criterion keys from the start) — an artifact of editing criteria under a live page.
- **Criterion-key coupling / response-key mismatch / weight_map — all FIXED `e6e4421d9`** (promoted to **SMK-018** above; it was NOT low-severity — real grants store `id` not `key`, so the manual scorer coupled on every real grant). `Grant.get_criteria()` now guarantees a stable `key`; the submit validator accepts id/key/index; the weight_map keys the same three. Verified end-to-end live: the wizard assigns `criterion_1`, an NGO submitted a response under that key (old validator would have rejected it), grant 448 criteria carry distinct keys.
